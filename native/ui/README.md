# openaec-ui

Native Rust shell, theme tokens, typography, semantic icons and controls shared by OpenAEC desktop tools. Implement `Application` and call `run`, or use `frame::FrameSlots` from an existing Iced event loop.

For a Frame Studio-style workspace, use `frame::workspace_frame` with `WorkspaceFrameSlots` and `WorkspaceFrameProfile::OPEN_FRAME`. This optional shell keeps the reviewed 36 px title and 28 px status bands, lets the ribbon and workspace tabs grow when they wrap, and places the application content between them. `frame::workspace_panes` supplies the reviewed 220/290 px default side widths when those panels are visible; the application may copy the profile and replace widths with persisted values. `status_bar_with_height` supplies the shared status treatment at the 28 px height. The [source comparison](../../design/frame-layout-review.html) records the measured Svelte geometry and contrast decisions. This is a reusable shell API, not yet a Frame Studio application migration.

For sidebar-first tools without a ribbon, `frame::sidebar_frame` and `SidebarFrameProfile::WORKSPACE_COMPOSER` provide the source-measured 32 px title, 220 px sidebar, and 22 px status bands. `ChromeMode::SidebarCompact` uses this frame in the shared runtime and passes the application's navigation through `Application::explorer` without adding a generic panel heading. The Style Repo's Workspace Composer review exercises Simple/Advanced navigation and all 18 pinned routes. Its package and preset cards are review interactions, not an installer backend or a pixel-matched migration.

`ChromeMode::ThreePaneFixed { left_width, right_width }` gives source-specific tools exact native pane widths while retaining the shared ribbon, document and status bands. The Calc screen review uses 320/240 px to reproduce the panel widths visible in the pinned Dutch capture; `App.tsx` initializes the left panel at 220 px, so this is a capture-state choice, not a changed Calc default.

`frame::status_bar` owns the shared 22 px status band, one-pixel top rule, theme colors and horizontal padding. An existing application supplies its own status cells and actions as an Iced `Element`; the same component is used by the Style Repo shell and Pointcloud Studio.

`widgets::title_action` owns the 30 × 26 px quick-access control, hover color and tooltip for the title strip. The Style Repo and Pointcloud supply their own command icons, labels and messages through this same Rust widget.

`widgets::themed_tooltip` owns the 12 px label, 8 × 12 px padding, 340 px maximum width and 8 px gap for ribbon, panel and status controls. The Style Repo ribbon and Pointcloud controls use this same tooltip; follow-cursor tips can override the gap.

`widgets::settings_modal` owns the source Style Book's 560 × 500 px settings chrome, 120 px sidebar, overlay, header and footer. Each app supplies its own tabs and settings fields. The backdrop does not dismiss the dialog, matching the pinned Tauri template.
`widgets::dialog_modal` owns the source Style Book's general modal: an application-selected width, 30 px header, square border, content surface, 44 px footer and inert full-window overlay. The source reset confirmation uses it at 340 px; Pointcloud's 2D drawing dialog and the Style Repo's interactive sample use it at 480 px. `Application::overlay` places domain dialogs above the complete shared shell, and `Application::escape` gives them Escape handling after the shared settings dialog.
The header uses the source top-to-bottom theme gradient, and `Theme::dialog_shadow` supplies its 0 × 4 px, 16 px-blur shadow in all five themes. The general and settings modals share these treatments.
Both modal variants are centered initially, can be dragged by the 30 px header without stealing the close button, stay within the application window, and cap their height at 90% of the viewport. The settings body scrolls when this cap reduces the available space.
`widgets::settings_tab` gives those tabs the same square 11 px navigation style. The crate shell provides selectable General, Appearance and About pages; other applications can supply their own page content and messages.
`widgets::settings_theme_picker` provides the 200 px trigger and anchored overlay menu with five choices and four 14 px swatches per row. It closes on an outside click without changing form layout. `Theme::swatches` is the single source of those colors for Style Repo and Pointcloud. Both apps own selection and preview behavior; the native review renders deliberately show the menu expanded.
`widgets::settings_reset_confirmation` renders the 340 px reset prompt above the settings modal. The crate shell previews theme, language and scale until Save; Cancel restores the values from when the dialog opened. Reset changes the preview only after confirmation. The shared runtime writes the preferences file on Save.

`frame::document_bar` owns the 30 px document band from the pinned Tauri Style Book: the one-pixel top and bottom rules, theme background and 4 px horizontal inset. Applications keep their own tab identity and navigation behavior.

`widgets::document_tab_style` and `widgets::document_close_style` give those app-owned tabs the shared 24 px appearance and a legible close action. Pointcloud retains its middle-click, shortening, scrolling and keyboard behavior while using the same visual tab styles as the Style Repo.

`widgets::ribbon_group` owns the 94 px ribbon-group geometry from the pinned Tauri template: 4 px top inset, 8 px sides, a ruled 9 px caption and a right separator. Applications pass their actual tools and measured group width. Pointcloud keeps its adaptive collapse and domain actions; the Style Repo uses the same group around its catalogue commands.

`model::RibbonControl` adds typed ribbon inputs to `Command`: a slider, a two-thumb range, a compact stack of sliders, segmented choices, select lists, numeric text input, compact labelled form stacks with number, select and slider rows, a color choice and a style gallery. Applications own the selected values and receive changes through their message type; `widgets::ribbon_control` draws the controls with the shared tokens. The range widget keeps both handles on one rail and supports mouse and touch dragging. Select lists accept application-owned labels, messages and width; slider stacks accept source-specific labels and icons within the same ribbon geometry. The color choice shows the current application color even when it came from a style preset outside the listed palette. `RibbonSwatch` carries a labelled color preview, an optional dashed border and an application message, so the gallery contains no PDF-specific meaning. The gallery shows an application-selected number of tiles and provides an aligned popup for the full set.

`widgets::color_grid` renders an app-owned palette in vertical columns with keyboard-focusable color buttons and tooltips. `widgets::popover` and `widgets::popover_aligned` anchor arbitrary app content over the shell, moves it above the anchor when there is insufficient room below, and closes on an outside click. `RibbonCustomColor` lets an application supply a validated custom-color editor inside the same popup. The Style Repo uses them together in the PDF ribbon; a software-rendered pixel test checks all 42 source colors in their 7 × 6 arrangement, and an event test checks palette actions and outside-click dismissal.

`widgets::backstage_nav_with` draws the shared 260 px File navigation with 40 px page rows, a selected accent mark, separators and Settings/Back/Exit footer. Applications provide translated pages, enabled actions and a theme resolver. The Style Repo shell uses it for catalogue navigation and hides its ribbon and document band while File is open; Pointcloud uses the same component for its seven real file pages. Pointcloud also anchors its Display controls with `popover_aligned`.

`backstage_page_heading`, `backstage_group_caption`, `backstage_task_tile_with` and `backstage_tile_column` draw the reusable File-page content rhythm. The tile column is limited to 620 px; each tile owns title/detail typography, a 4 px border and enabled/disabled/hover colours, while applications supply translated content and actions. Pointcloud uses these for its New, Open, Import and Export tasks; the Style Repo components page shows enabled and disabled examples.

`widgets::form_field` provides a labelled, application-owned input for full-page screens; the Style Repo uses it in the native Field Project form. `widgets::property_grid_row_with`, `property_grid_control_with`, and `property_section_with` provide the shared properties dock. Rows are 28 px high with aligned label and value columns and a bottom rule; section headers are 24 px high. Callers supply their own localized text, input controls and theme resolver. The Style Repo shows a live scale slider in the control grid; Pointcloud uses the same rows for its six section-box sliders and editable layout viewport fields.

`find_bar::view` draws a native document search overlay from the pinned PDF Studio FindBar, with its five verified UI SVGs, 24 px input, 22 px navigation buttons and source filters. Pass the document viewport width so options move to a second row below 370 px; the application owns query, results, navigation and keyboard shortcuts through `FindBarState` and `FindBarActions`. The Style Repo's Components page and standalone example have interactive samples and a [software-rendered review](../../design/pdf-find-bar-screen-review.html); the Pointcloud snapshot includes the component for future use.

This package contains the shared Rust implementation, six bundled fonts with their [separate license notices](NOTICE.md), 35 canonical control icons including the source-reviewed Speech microphone and the Geotechniek-reviewed Print, Save As and Restore commands, and 36 reviewed domain meanings with separate 16 px artwork: four from CAD/Pointcloud, three geotechnical placement symbols, four drawing/transform commands shared by Geotechniek and Pointcloud, five CAD editing commands reviewed against Geotechniek and OpenCAD, three Geotechniek drawing/frame commands, two Pointcloud drawing-annotation commands (Text and Leader), and fifteen PDF ribbon meanings reviewed against seven source icon collisions. `icons::DomainIcon` and `model::CommandIcon::Domain` keep those commands distinct from the general `icons::Icon` set. `Icon::Settings` is a gear for app settings; `Icon::Controls` retains the slider symbol for view/property controls. The 32 `ribbon_icons::RibbonIcon` variants carry source-used Style Book Tauri ribbon vectors with distinct command meanings. Applications still supply their own command behavior and screens. Source icons collected for design research, unapproved FEM/BIM drafts and Style Repo screenshots live in the sibling `openaec-style-repo` application and are not included in this crate package.

The PDF meanings distinguish Fit Width, Actual Size, Edit Text, Clear Page, Delete Page, Single Page, Continuous Pages, File Association, Book View, Shortcuts, Navigation, Manage Watermarks, Proofread and Split Document. Fit Page, Find, and Text Annotation reuse `Icon::Fit`, `Icon::Search`, and `DomainIcon::DrawingText`. Seven PDF meanings have separate optically simplified 16 px vectors, including IFC report export, which combines a cube with an outgoing arrow missing from the source UI icon. Proofread and Split Document follow reviewed, actually used ribbon commands in public PDF main `ae1d787`; the compare split-mode illustration is not part of this command API. These semantics are available to tools through the crate, but the original PDF Studio JavaScript application has not been migrated.

The [private OpenAEC Style Repo](https://github.com/OpenAEC-Foundation/OpenAEC-Style-Repo) is the canonical Git source for this crate. Pointcloud carries a verified local snapshot so its public checkout remains buildable without private repository access; run `python3 scripts/check_portable_ui.py` from the Style Repo to check source and asset parity. The sibling Style Repo application documents the source inventory and the Pointcloud integration.
