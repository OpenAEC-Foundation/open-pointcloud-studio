# Competitor findings: what Open Pointcloud Studio needs next

Reviewed 5 November 2026 against main `afe5c0c`. This is a desk review of official documentation and an audit of this repository, not a hands-on competitor benchmark. Recommendations below are our judgement; vendor capabilities are documented claims. Editions and platforms can differ.

## Recommended direction

Finish a reliable **scan → clean/select → align → draw/model → verify → deliver** workflow. Import, viewing, point-pair registration, ICP, panorama editing, meshing, CAD lines, sheets, PDF, BCF and automation already exist. Rebuilding those because a competitor advertises them would waste work.

The most useful next steps are understandable quality evidence, repeatable drawing delivery and validated downstream exchange. Reversible cleanup/classification is the next bounded capability to investigate. Full photogrammetry, nationwide automatic building reconstruction and a general cloud viewer are specialist expansions, not immediate requirements for this desktop application.

## Findings by competitor

| Product and official evidence checked | What matters | Existing Open Pointcloud Studio capability | What we should do |
| --- | --- | --- | --- |
| [CloudCompare methods](https://www.cloudcompare.org/doc/wiki/index.php/Methods), [SOR filtering](https://www.cloudcompare.org/doc/wiki/index.php/SOR_filter) and [distance definitions](https://www.cloudcompare.org/doc/wiki/index.php/Distances_Computation) | Registration, segmentation, filters, cloud-to-cloud and cloud-to-mesh comparisons. | Point pairs, ICP, residuals, transforms, selections and fitted-face/mesh quality metrics. | Prioritise a readable registration/quality summary that distinguishes fit residual, distance to a reference and missing overlap. Investigate reversible statistical-noise cleanup on the selected region. Do not call a fitted surface a design reference. |
| [PointCab Origins changelog](https://pointcab-software.com/en/newsroom/changelog/) and [layouts/sections](https://pointcab-software.com/en/learn/layouts_and_sections/) | Origins 4.3 lists automatic layouts by floor, CAD sketch export, vector tools and additional section/mesh operations. | Pointcloud to Drawing already surveys levels and persists its project; drawing creation, straight CAD lines, sheets and CAD/PDF exports exist. | Test a complete two-storey drawing set rather than propose another floor detector. Preserve common cuts, units, origin, layers and annotations through reruns. Only implement a batch-delivery gap after reproducing it in the existing workflow. |
| [Autodesk ReCap Pro](https://www.autodesk.com/products/recap/overview) | Scan-to-mesh and delivery into Revit, with cloud-based extraction/sharing. | Native meshes and a documented E57 ReCap handoff, with stations/photos retained where supported. | Validate the exported file in actual ReCap on Windows and then in the intended CAD/BIM workflow. Keep the documented distinction between supported spherical panoramas and other camera models. An E57 schema check is not a ReCap import test. |
| [Leica Cyclone 3DR BIM analysis](https://leica-geosystems.com/products/laser-scanners/software/leica-cyclone/leica-cyclone-3dr/powerful-bim-analysis) | Tolerance checking, coverage, reports, colourmaps and object-linked BCF notes. | BCF viewpoints, meshes, fitted faces, deviation colours and numerical quality metrics. | Build towards reviewable inspection outputs. First define the reference object and sampling; report no-data separately from pass/fail. Generic BCF viewpoints are not equivalent to IFC-object-linked inspection. Model-reference inspection needs a separate design before promising BIM compliance. |
| [Trimble RealWorks](https://www.trimble.com/en/products/building-construction-field-systems/trimble-realworks) | Large dataset processing, registration, modelling and deviation deliverables. | Indexed viewport, multiple scans, selections, mesh/face extraction and export automation. | Audit a multi-scan project from opening through export: recovery, role selection, hidden/deleted points, coordinate frames and output provenance. Require evidence on large inputs before claiming competitive performance. |
| [FARO SCENE processing/registration](https://knowledge.faro.com/Software/FARO_SCENE/SCENE/Processing_Scans_in_SCENE) | Target/top-view/cloud alignment, filtering, colourisation and registration statistics; target distribution can invalidate a registration. | Point-pair/ICP alignment, per-pair errors, coloured sample and station/photo support. | Make weak geometry, low overlap and independent check points understandable. Prioritise actionable quality messages over adding more alignment buttons. Target recognition and multi-station network adjustment are later research topics if users need them. |
| [RIEGL RiSCAN PRO](https://www.riegl.com/en-canada/products/detail/riscan-pro) | Registration, multi-station adjustment, filtering, georeferencing and batch processing. | Reusable transforms, registered mixed-format exports, original station-pose retention, CLI/API/MCP. | Validate control-point/CRS workflows and static/kinematic combinations. Explain that a rigid transform cannot remove internal SLAM drift. Keep original source names, poses and coordinates traceable in outputs. |
| [TerraScan](https://terrasolid.com/products/terrascan/), [macros](https://terrasolid.com/guides/tscan/intromacros.html) | Classification, large tiled projects, vector extraction and repeatable processing sequences. | Class display/filtering, point selection/deletion/thinning, terrain meshes, indexed input and scriptable operations. | Investigate preview/apply/undo for selected-point classification and outlier filtering. Reuse existing job/cancellation and edit-mask mechanisms. Start with one bounded building/terrain task; a nationwide automated classifier is a different product scope. |
| [3DF Zephyr mesh extraction](https://www.3dflow.net/zephyr-doc/en/Extractingamesh.html) | Watertightness, colour updates and image-based optimisation trade quality against processing effort. | Terrain/surface/closed meshes, sample limits, simplification, mesh quality and colour/texture export. | Explain where holes were filled and how far the result departs from observations. Compare reconstructed geometry to source points with declared sampling. Treat a full photo-reconstruction engine as a later specialist integration. |

Leica's registration product is a separate reference: [Cyclone REGISTER 360 PLUS reports](https://rcdocs.leica-geosystems.com/v1/docs/cyclone-register-360-registration-report) combine a quality matrix, bundle/link/target errors and images. Its [error-reporting guide](https://rcdocs.leica-geosystems.com/docs/cyclone-register-360-error-reporting) explains that error definitions differ even between its own products and recommends visual checks alongside numbers. For us, that supports a clearly defined quality summary with contextual evidence, not a single unexplained “accuracy” value.

## Priority and acceptance evidence

| Priority | Outcome | Minimum evidence before shipping follow-up work |
| --- | --- | --- |
| First | Reviewable quality summary | Identify sources and transforms, selected region, coordinate units, algorithm/settings and sampling. Define each metric and no-data/overlap. Export machine-readable evidence plus a readable summary; do not present a sampled maximum as the whole-scan maximum. |
| First | Reliable drawing-set delivery | Reopen a two-storey project and regenerate its plans/sections without re-entering settings. Check filenames, layers, units, dimensions and stale outputs; inspect the PDF and reopen CAD outputs in an independent reader. |
| First | Proven exchange and source preservation | Run actual receiving-tool checks with ReCap/CAD/BIM. Count retained points, check station/image associations and verify world coordinates against independent checks. State untested vendors/camera models explicitly. |
| Next | Reversible cleanup/classification | Preview the effect in a selected box; show changed/retained point counts; apply, cancel and undo. Confirm all exports honour the edit, including indexed full-resolution sources. Test sparse boundaries and large coordinates; never remove points silently. |
| Later | Design-reference inspection | Define supported reference geometry, transforms, distance sign, tolerance and coverage semantics. Demonstrate a known displacement and a no-data case. Decide whether and how IFC object identity is retained in BCF. |
| Later | Repeatable processing recipes | Reuse CLI/API and persisted projects; record settings and source identity. Resume safely and make partial failures visible. Add a GUI only for a confirmed workflow need. |

[Potree](https://potree.org/potree/examples/github.html), [PDAL](https://pdal.io/en/latest/stages/filters.html) and [MeshLab](https://www.meshlab.net/) remain useful complementary references for navigation, reproducible point processing and mesh inspection. They are not equivalent desktop competitors. Offline processing, BCF and editable CAD export are shared capabilities; avoid uniqueness claims.

Recommendations above are not automatically confirmed defects. This review creates no additional competitor-feature issues. Each future issue needs an actual current gap, related-issue/comment/PR and code checks, user impact and testable acceptance criteria. Recheck immediately before creation because implementation and issue states change.

## Immediate implementation requested alongside this research

The native title strip gains a Feedback action backed by Open Feedback Studio's explicit private route. It sends only the form's category/title/description, optional reply email and app version, on the user's Send action. It attaches no scans, paths, screenshots or logs. Failures retain the draft, and success requires an explicit private-storage acknowledgement. The integration follows Open Feedback Studio source `a633fd1`, including its explicit private route. Mock HTTP tests exercise the service contract without sending test messages to the live service. A live request with an empty object is rejected with HTTP 400 (`App identifier is required`), confirming that the validation route is reachable; successful live storage is not claimed by that probe.

The bottom-right MCP server checkbox controls the external local command bridge. Pausing blocks new owner-token MCP/API commands and queued GUI commands, while extension grants and already-running jobs continue. Discovery remains available so clients can recognise the paused window. The preference is saved; a failed listener is shown as unavailable. The stdio MCP process is still launched by its AI client; the checkbox does not claim an AI client is connected or start a cloud service.
